## Image

```
ghcr.io/eugenioenko/autentico:latest
```

The image is a minimal Linux container with just the `autentico` binary. The entrypoint is `./autentico` and the default command is `start`.

The listener uses the same [HTTP timeouts as binary deployments](/deployment/binary/#http-timeouts).

## Quick start

```bash
docker run -d \
  --name autentico \
  -p 9999:9999 \
  -v autentico-data:/app/data \
  --restart unless-stopped \
  ghcr.io/eugenioenko/autentico:latest \
  start --auto-setup
```

On first run, `--auto-setup` generates a `.env` with fresh secrets and persists it on the volume. On subsequent restarts, the existing configuration is reused.

Open `http://localhost:9999/onboard` to create your admin account.

## Custom URL

```bash
docker run -d \
  --name autentico \
  -p 9999:9999 \
  -v autentico-data:/app/data \
  -e AUTENTICO_APP_URL=https://auth.example.com \
  --restart unless-stopped \
  ghcr.io/eugenioenko/autentico:latest \
  start --auto-setup
```

## Using a pre-generated .env

If you prefer to manage secrets explicitly:

```bash
# Generate .env locally (requires the binary)
autentico init --url https://auth.example.com
```

```bash
docker run -d \
  --name autentico \
  -p 9999:9999 \
  -v autentico-data:/app/data \
  --env-file .env \
  --restart unless-stopped \
  ghcr.io/eugenioenko/autentico:latest
```

## Environment variables

All configuration is via [Bootstrap Settings](/configuration/bootstrap/). Key variables:

| Variable | Required | Notes |
|---|---|---|
| `AUTENTICO_APP_URL` | No | Public URL. Defaults to `http://localhost:9999`. Used in OIDC discovery and redirects. |
| `AUTENTICO_DB_FILE_PATH` | No | SQLite database path. Defaults to `./autentico.db`. |
| `AUTENTICO_LISTEN_PORT` | No | Port the server binds to. Defaults to the port in `AUTENTICO_APP_URL`. |
| `AUTENTICO_TOTP_ENCRYPTION_KEY` | Yes | Persistent base64-encoded 32-byte TOTP encryption key. Keep the same key for migration, restarts and database restores. |

Fresh `init` and fresh `--auto-setup` generate `AUTENTICO_PRIVATE_KEY`, `AUTENTICO_CSRF_SECRET_KEY`, `AUTENTICO_ACCESS_TOKEN_SECRET`, `AUTENTICO_REFRESH_TOKEN_SECRET`, and `AUTENTICO_TOTP_ENCRYPTION_KEY`. Environment-managed production deployments must supply all five and retain them across restarts.

For an existing `.env`, the updated `init` command adds only a missing TOTP encryption key, preserving other settings and signing secrets. Startup does not silently add a key to an existing configuration. Before upgrading to v3, follow [the migration guide](/deployment/migrations/) to prepare the persistent key, stop the old service and approve the migration. Existing authenticator enrollments are encrypted in place and preserved.

## Health check

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s \
  CMD wget -qO- http://localhost:9999/healthz || exit 1
```

## Logs

Autentico logs structured HTTP access logs to stdout. Collect them with your Docker logging driver.

<Aside type="tip">
For production setups with a reverse proxy, see [Docker Compose](/deployment/docker-compose/).
</Aside>

<Aside type="caution" title="URL mismatch">
Changing `AUTENTICO_APP_URL` after first run leaves the admin client registered with the old callback URL. Delete the volume and start fresh: `docker stop autentico && docker rm autentico && docker volume rm autentico-data`.
</Aside>
