By default, Autentico operates as a closed system — only admins can create user accounts. Self-signup allows users to register their own accounts from the login page.

## Enabling self-signup

Self-signup is controlled by the `allow_self_signup` runtime setting:

```bash
curl -X PUT https://auth.example.com/admin/api/settings \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"allow_self_signup": "true"}'
```

When enabled, a **Create account** link appears on the login page, pointing to `/oauth2/authorize?prompt=create`.

## Per-client control

Self-signup can be enabled for specific clients only while remaining disabled globally:

```json
{
  "client_name": "Community Forum",
  "allow_self_signup": true
}
```

The signup page checks the `allow_self_signup` setting for the originating client. If no per-client override is set, it falls back to the global setting.

## Signup flow

1. User clicks **Create account** on the login page
2. User fills in username, password, and (if `validation_email_required` is `true`) email
3. Autentico validates the input against the configured validation rules
4. If valid: creates the user account and redirects back to the login page
5. User logs in with their new credentials

## Validation rules

The same username and password validation rules apply at signup as at admin-created accounts. See [Password Authentication](/authentication/password/) for the validation settings reference.

Consider enabling [Email Verification](/authentication/email-verification/) alongside self-signup to validate user email addresses.

<Aside type="caution">
Enabling self-signup means anyone can create an account. Consider pairing it with email verification (`validation_email_required = true`) or manual review before allowing access to sensitive clients.
</Aside>

## Invite-only signup

Leave public self-signup disabled and open **Admin → Users → Signup invites → Create invite**. Recipients register through the built-in account client with the configured password or passkey flow. New accounts have the user role and ordinary application access rules apply.

| Invitation | Recipient and delivery | Use limit |
|---|---|---|
| Personal | Copy the URL, optionally restrict it to an email address, or select **Send email invite** when SMTP is configured. | One completed signup. |
| Shared | Copy one URL for a group. Each person supplies their own account details. | Choose a positive number of signups or **Unlimited uses**. |

Invitations expire after seven days by default. Pick a different expiration when creating one. Shared links can also have **No expiration**. Anyone with an unlimited, non-expiring link can register until an administrator revokes it.

Copy a generated URL before leaving the page. Email delivery keeps the URL private to the recipient and verifies the bound address on redemption. **Resend email** rotates the URL, invalidating earlier copies. A manually copied link follows normal email verification policy. A link with no bound address can be used without email when the instance's signup policy permits it.

The list shows usage, expiry and revocation status. Opening a link or abandoning the form leaves the remaining count intact. If the signup page has been open for over 30 minutes, reopen the invitation URL to continue.
